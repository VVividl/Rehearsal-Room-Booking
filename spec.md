# Специфікація моделі даних: Rehearsal Room Booking (spec.md)

## 1. Опис сутностей та їх атрибутів

### Client (Клієнт)
Позначає зареєстрованого користувача репетиційної бази (музиканта або представника гурту), який здійснює бронювання залів та обладнання.
* `client_id` (PK) - унікальний ідентифікатор клієнта.
* `first_name` - ім'я клієнта.
* `last_name` - прізвище клієнта.
* `email` - контактна електронна пошта.
* `phone_number` - номер телефону для зв'язку.

### Room (Репетиційна кімната)
Описує конкретний репетиційний зал студії з його технічними лімітами та базовою вартістю.
* `room_id` (PK) - унікальний ідентифікатор кімнати.
* `room_name` - назва або маркування зали.
* `capacity` - максимальна місткість осіб в кімнаті.
* `hourly_room_rate` - актуальна базова ставка оренди зали за одну годину.

### Booking (Бронювання)
Описує факт резервування репетиційного залу конкретним клієнтом на певний проміжок часу.
* `booking_id` (PK) - унікальний ідентифікатор бронювання.
* `client_id` (FK -> Client.client_id) - ID клієнта, що створив бронювання.
* `room_id` (FK -> Room.room_id) - ID заброньованої кімнати.
* `booking_status` - статус життєвого циклу заявки (наприклад, PENDING, CONFIRMED/RESERVED, CANCELLED, COMPLETED).
* `start_datetime` - дата та час початку репетиційної сесії.
* `end_datetime` - дата та час завершення репетиційної сесії.
* `total_price` - розрахована фінальна вартість замовлення.

### Equipment (Додаткове обладнання)
Каталог додаткового музичного інвентарю та інструментів, доступних для тимчасової оренди на час сесії.
* `equipment_id` (PK) - унікальний ідентифікатор одиниці інвентарю.
* `equipment_name` - назва моделі або типу інструмента.
* `category` - тип беклайну (барабани, комбопідсилювач, мікрофон).
* `equipment_status` - експлуатаційний стан одиниці (AVAILABLE, MAINTENANCE).
* `hourly_equip_rate` - поточна базова вартість оренди одиниці за одну годину.

### BookingEquipment (Оренда обладнання у бронюванні)
Асоціативна сутність зв'язку M:N між сесією репетиції та додатковим інвентарем.
* `booking_equipment_id` (PK) - унікальний ідентифікатор запису позиції.
* `booking_id` (FK -> Booking.booking_id) - ID бронювання, до якого включено техніку.
* `equipment_id` (FK -> Equipment.equipment_id) - ID орендованого інструмента.
* `quantity` - кількість одиниць замовленого обладнання.
* `hourly_booking_rate` - зафіксована погодинна вартість оренди на момент створення замовлення (збереження історичної вартості).

---

## 2. Зв'язки між сутностями

* **Client ↔ Booking (1:N):** Клієнт може мати 0 або багато бронювань. Одне бронювання належить рівно одному клієнту.
* **Room ↔ Booking (1:N):** Кімната може фігурувати в 0 або багатьох бронюваннях на різні часові слоти. Одне бронювання закріплене за однією кімнатою.
* **Booking ↔ BookingEquipment (1:N):** Бронювання може містити 0 або багато додаткових позицій обладнання. Кожен рядок оренди техніки належить рівно одному бронюванню.
* **Equipment ↔ BookingEquipment (1:N):** Позиція каталогу обладнання може бути орендована у 0 або багатьох бронюваннях. Кожен рядок посилається на один конкретний тип техніки.
* **Booking ↔ Equipment (M:N):** Зв'язок реалізовано опосередковано через проміжну сутність `BookingEquipment`.

---

## 3. Критерії прийняття (Acceptance Criteria)

* **Нормалізація (3NF):** Відсутність дублювання атрибутів (контактні дані зберігаються виключно в `Client`, технічні параметри — у каталогах). Немає неатомних списків у полях.
* **Відсутність неявних Many-to-Many:** Зв'язок між замовленням і каталогом техніки повністю розв'язаний через асоціативну сутність `BookingEquipment`.
* **Історичність тарифів:** Зміна тарифів у таблицях `Equipment` або `Room` не змінює фінансові показники старих замовлень завдяки наявності полів `hourly_booking_rate` та підсумкового `total_price`.
* **Цілісність даних:** Кожна таблиця містить однозначний первинний ключ (PK). Усі зовнішні ключі (FK) однозначно посилаються на батьківські сутності без висячих посилань.
